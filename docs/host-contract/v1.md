# Helm Host Probe Contract — v1

A versioned, delimited record stream produced by a single host-side probe. Any
language can implement a conformant reader from this document alone. One bad
byte degrades only the record it appears in — the rest of the stream still
parses.

This document is the contract. It has no dependency on Dart, Flutter, or the
Helm codebase. A TypeScript, Go, or Python implementation needs nothing else.

## Delivery

The probe travels as a POSIX `sh` script piped to the remote host's stdin,
executed as `sh -s` with **no pseudo-terminal**. It creates, writes, installs,
and caches nothing on the host — it is safe to send on every connection.

Two reasons for this delivery mechanism:

1. The exec command is the fixed two-token literal `/bin/sh -s`, which every
   login shell (bash, zsh, fish, csh, dash) can invoke without parsing the
   script itself. Running the script *as* the exec string instead would force
   sshd to interpret it with `$SHELL -c '<script>'`, and a fish/csh login
   shell cannot parse a POSIX script.
2. With no PTY, stdin and stdout are separate streams. With a PTY, they share
   one tty, which echoes the script bytes back into stdout and corrupts the
   record stream.

## Grammar

```
line 1        : "helm-probe/1" LF                 -- exact bytes, no fields
line 2..n-1   : <kind> TAB <field> [TAB <field>]* LF
last line     : "end" TAB <status> TAB <elapsed_ms> LF
```

Framing is TAB-delimited (`\t`, 0x09), LF-terminated (`\n`, 0x0A). Every
**value** is escaped by the probe before emission; the TAB and LF delimiters
themselves are never escaped, because they never appear literally inside a
value once escaping has run.

If the terminating `end` record is missing — for example because the
connection dropped mid-stream — the reader MUST treat the whole report as
**truncated**, never as "a host with zero sessions". This is why `end`
exists as an explicit record rather than being inferred from stream close.

## Escape table

The complete table. Four rules, one pass, decodable in a handful of lines in
any language:

| Raw byte | Emitted as |
|---|---|
| `\` (0x5C) | `\\` |
| TAB (0x09) | `\t` |
| LF (0x0A) | `\n` |
| CR (0x0D) | `\r` |

Decoding reverses this: scan for `\`, and interpret the following character
as `\` → `\`, `t` → TAB, `n` → LF, `r` → CR. Any other character following an
unescaped `\` is not a valid escape sequence for this contract; a conformant
reader should keep the backslash literally rather than fail the record.

This is why the contract is a delimited stream and not JSON: a POSIX-`sh`
JSON escaper must also handle `"` and `\uXXXX` control-code forms, is easy to
get subtly wrong, and one bad byte corrupts the *whole document*. Here a bad
byte corrupts *one record*, and every other record still parses.

## Record kinds (v1)

| kind | fields | meaning |
|---|---|---|
| `env` | `key`, `value` | One host environment fact. Known keys: `path_inherited`, `path_repaired`, `uname`, `shell`, `user`, `home`, `herdr_mobile_config` |
| `mux` | `id`, `found` (`0\|1`), `abs_path`, `version`, `on_inherited_path` (`0\|1`) | Multiplexer install state. Emitted for **every** known multiplexer (`herdr`, `tmux`, `zellij`) on every probe, whether or not it was found |
| `session` | `mux_id`, `name`, `state` (`active\|exited\|unknown`), `attached` (`0\|1\|unknown`) | One session belonging to `mux_id` |
| `agent` | `mux_id`, `session`, `target`, `label`, `state` (`idle\|working\|blocked\|done\|unknown`) | One AI-agent's state within a session, on multiplexers that expose it |
| `diag` | `id`, `status` (`ok\|warn\|unsupported\|unknown`), `detail` | One host diagnostic finding |
| `err` | `scope`, `detail` | A bounded partial failure that did **not** abort the probe |
| `end` | `status` (`ok\|partial`), `elapsed_ms` | Terminates the stream and reports overall status |

The `env` key namespace is **open**: the table above lists the keys this
version emits, not an allowlist. A reader encountering an unrecognized key
keeps it like any other environment fact — that is what makes a new host
fact addable without a parser change.

`herdr_mobile_config` is the one key emitted **conditionally**. It carries
the absolute path of a herdr config file that exists on the host
(`$XDG_CONFIG_HOME`, else `$HOME/.config`, then `herdr/config.mobile.toml`),
and is omitted entirely when no such regular file is there. It reports the
path it actually tested rather than a `0|1` flag, so a client never has to
reconstruct a location it did not verify. Unlike `mux`, "absent" and "not
checked" are deliberately indistinguishable here: both mean a client MUST
proceed exactly as it would with no key at all, so nothing is gained by
telling them apart.

`mux` is emitted for **all three** known multiplexers on every probe, so a
client can offer switching and can distinguish *"herdr is installed at
`/opt/homebrew/bin/herdr` but is off your non-interactive shell's PATH"* from
*"herdr is not installed"* — the difference between `found=1,
on_inherited_path=0` and `found=0`. Many non-interactive SSH sessions skip
shell rc files entirely (and some distributions' stock rc files return early
for non-interactive shells), so a binary installed via a package manager can
be genuinely present yet invisible to a bare `command -v`. The probe repairs
`PATH` itself before resolving each binary, and reports both the original
inherited `PATH` (`env path_inherited`) and the repaired one (`env
path_repaired`) so a reader can reconstruct exactly what changed.

## Evolution rules (normative)

| Rule | Reader behavior |
|---|---|
| Unknown `kind` | **Skip the record.** Never fail the parse. |
| Extra trailing fields on a known kind | **Ignore them.** Fields are append-only within a major version. |
| Missing `end` record | Treat the report as **truncated**, not as "no sessions". |
| First line is not exactly `helm-probe/1` | **Refuse and report a version mismatch.** Never guess-parse a different major version. |

Fields are never reordered or removed inside a major version — only appended.
A conformant reader written against v1 will still correctly read every v1
field of a future v1.x probe; it will simply see none of the new ones.

## Worked examples

### Happy path

```
helm-probe/1
env	path_inherited	/usr/bin:/bin
env	path_repaired	/usr/local/bin:/usr/bin:/bin
env	uname	Linux dev 6.1.0 x86_64
env	shell	/bin/bash
env	user	dev
env	home	/home/dev
mux	herdr	0			0
mux	tmux	1	/usr/bin/tmux	tmux 3.3a	1
mux	zellij	0			0
session	tmux	work	active	1
end	ok	42
```

A reader parses this into: 6 environment facts, 3 multiplexer entries (herdr
not found, tmux found and on the inherited PATH, zellij not found), 1 tmux
session named `work` that is active and attached, and a completed report
that took 42ms.

### One malformed record among well-formed ones

```
helm-probe/1
env	shell	/bin/bash
mux	tmux
env	user	dev
end	ok	10
```

The `mux` record above declares only one field (`tmux`) where the `mux` kind
requires five. A conformant reader drops **only that record** — the two
`env` records before and after it, and the `end` record, still parse and
appear in the result. The malformed record never blocks its siblings.

### Truncated stream

```
helm-probe/1
env	shell	/bin/bash
mux	tmux	1	/usr/bin/tmux	tmux 3.3a	1
```

No `end` record appears. A conformant reader MUST report this as
**truncated**, never as "a host with zero sessions" — the connection may
simply have dropped after the `mux` line, and any sessions after it are
unknown, not absent.

### Version mismatch

```
helm-probe/2
env	shell	/bin/bash
end	ok	5
```

The first line is not exactly `helm-probe/1`. A conformant reader MUST
refuse the whole report as a version mismatch and MUST NOT attempt to parse
any of the following lines, even though they look well-formed.

### A value containing reserved bytes

A tmux session literally named `weird` + TAB + `name` (unusual, but session
names are user-controlled) is emitted as:

```
session	tmux	weird\tname	active	0
```

Decoding the third field (`weird\tname`) reverses the escape table: the
literal two-character sequence `\t` becomes one TAB byte, so the decoded
session name is `weird<TAB>name` — the exact original bytes, not the four
characters `w`, `e`, `i`, `r`, `d`, `\`, `t`, ...
